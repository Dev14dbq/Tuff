# Мир 26.3 (DataVersion 5023): как он хранится и как мы это проверяем

Источники: публичная документация (minecraft.wiki: «Region file format», «Chunk format», «Java
Edition level format») и файлы, которые сохранил ванильный сервер 26.3 (`cargo xtask
chunk-info`). Код Mojang для этого не читался.

## Папка мира

- `level.dat`: NBT в gzip. Точка спавна — `Data.spawn {pos: [x, y, z], yaw, pitch,
  dimension}`. В старых мирах это `Data.SpawnX/Y/Z`, поддерживаем оба варианта.
- **Измерения лежат в `dimensions/<namespace>/<имя>/`**: `region/`, `entities/` и т.д. Например,
  `dimensions/minecraft/overworld/region/r.0.0.mca`. В старых версиях было `region/` в корне.

## Файл региона (`r.<x>.<z>.mca`)

Сектора по 4 КиБ. Сектор 0: 1024 записи о месте (3 байта смещения + 1 байт числа секторов).
Сектор 1: 1024 метки времени. Чанк: 4 байта длины, байт сжатия (1 gzip, 2 zlib, 3 нет,
4 LZ4, 127 своё; бит 0x80 — данные во внешнем `c.<x>.<z>.mcc`), затем NBT. LZ4 и своё
сжатие мы пока не читаем, ваниль по умолчанию пишет zlib.

## NBT чанка

- `Status`: только `minecraft:full` — готовый чанк. Остальные (недогенерированные края) клиенту
  не отправляем. В 26.4 ключ переименуют в `status`, читаем оба.
- `sections`: 24 штуки для верхнего мира, `Y` от −4 до 19.
  - `block_states.palette`: **список строк**, если все состояния по умолчанию. Иначе **список
    compound'ов**: `{"": "minecraft:dirt"}` для состояния по умолчанию (обёртка разнотипного
    списка NBT) и `{id, properties: {...}}` для остальных.
  - `block_states.data`: индексы как в протоколе, не меньше 4 бит. При одном элементе палитры
    данных нет.
  - `biomes.palette` (строки) и `biomes.data` (минимум бит, без нижней границы).
  - `SkyLight` и `BlockLight` по 2048 байт, **только у секций, где свет хранится**. Небо обычно
    лежит у 2–4 секций рядом с поверхностью, выше — нет.
- `Heightmaps`: `MOTION_BLOCKING`, `MOTION_BLOCKING_NO_LEAVES`, `WORLD_SURFACE`, `OCEAN_FLOOR`.
  Клиенту отдаём первые три.
- `block_entities`: `{id, x, y, z, ...}`.

## Что получает клиент

- **Свет**: как хранится. Секции с массивом попадают в маску, секции без массива — ни в какую
  маску. Ваниль делает так же.
- **Блок-сущности**: только то, что нужно для отрисовки. Сверено с ванилью: сундук получает пустые
  данные (TAG_End), спавнер — свои данные без `SpawnPotentials` и `components`. Для остальных
  типов пока убираем `Items`, `LootTable`, `LootTableSeed`, `components`. Это предположение, его
  проверим, когда начнём ставить блоки.

## Тестовый мир и проверка

Ванильный сервер в `cache/vanilla-server/26.3` (offline, 127.0.0.1:25570). Мир `world-normal`
(сид `minecraft-rewrite`), область 16×16 чанков вокруг спавна сгенерирована командой
`forceload add` из консоли сервера.

```bash
# раздать ванильный мир нашим сервером
cargo run --release -p mc-server -- --offline --world cache/vanilla-server/26.3/world-normal

# сравнить чанки: ваниль (с `tick freeze`, чтобы мир не менялся) против нашего
cargo xtask probe --addr 127.0.0.1:25570 --batches 30 --dump /tmp/a
cargo xtask probe --addr 127.0.0.1:25565 --batches 30 --dump /tmp/b
cargo xtask chunk-diff /tmp/a /tmp/b
```

Результат: **49 из 49 общих чанков совпадают** по блокам, биомам, heightmap, свету неба и блоков
и блок-сущностям. Без `tick freeze` расходятся 1–2 блока на чанк. Это живой мир ванили: трава
распространяется, овцы едят траву, растёт тростник. Разбор тут ни при чём.

`cargo test -p mc-storage` разбирает все 1764 сохранённых чанка тестового мира (400 полных).
Все блоки и биомы палитр распознаются. Каждый полный чанк кодируется обратно поверх своего NBT,
снова разбирается и совпадает с исходным. Ни один ключ верхнего уровня не теряется.

## Запись

- **Чанк записывается поверх своего сохранённого NBT.** Заменяются `sections` (палитры, биомы,
  свет), `Heightmaps` и `block_entities`. Остальное, что мы пока не моделируем, остаётся как было:
  `structures`, `block_ticks`, `fluid_ticks`, `PostProcessing`, `InhabitedTime`. Секции за
  пределами высоты мира (только свет) тоже не трогаются.
- **Палитра записывается сжатой**: только используемые состояния, в порядке первого появления.
  Состояние по умолчанию пишется строкой, остальные — `{id, properties}`. Смешанный список
  оборачивается так же, как у ванили.
- **В изменённых чанках `isLightOn` = 0**, потому что сохранённый свет устарел. По наблюдению,
  ваниль после загрузки такого чанка отдаёт клиенту сохранённый свет как есть и сразу его не
  пересчитывает. Значит, правильный свет после правок даст только наш движок освещения
  (`mc-light`).
- **Регион.** Чанк сжимается zlib и пишется в свободные сектора, никогда поверх своей старой
  копии. Сначала пишутся данные, потом запись в заголовке. Если чанк длиннее 255 секторов, он
  уходит во внешний `c.<x>.<z>.mcc`.
- Автосейв каждые 5 минут (`--autosave`), плюс сохранение при остановке (Ctrl-C). Плоский
  тестовый мир живёт только в памяти.

### Проверка: ваниль открывает то, что сохранили мы

```bash
cp -R cache/vanilla-server/26.3/world-normal cache/vanilla-server/26.3/world-edit
cargo run --release -p mc-server -- --offline --port 25566 --world cache/vanilla-server/26.3/world-edit
cargo xtask blocks --addr 127.0.0.1:25566        # строим, затем Ctrl-C: сервер сохраняет
# ваниль с level-name=world-edit и `tick freeze`, наш сервер на копии того же сохранения
cargo xtask probe --addr 127.0.0.1:25570 --batches 30 --dump /tmp/a
cargo xtask probe --addr 127.0.0.1:25566 --batches 30 --dump /tmp/b
cargo xtask chunk-diff /tmp/a /tmp/b
```

Результат (2026-10-17): ваниль загрузила изменённый чанк без ошибок. **48 из 49 общих чанков
совпадают**, в том числе изменённый: блоки, биомы, heightmap, свет, блок-сущности. Единственное
расхождение — в чужом чанке. Там ванильная трава успела разрастись на землю до `tick freeze`.
