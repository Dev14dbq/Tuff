# Протокол 26.3 (777): где игра расходится с документацией

Основной источник форматов — публичная документация протокола (minecraft.wiki, «Java Edition
protocol»). Ниже то, что в ней устарело или чего там нет. Всё найдено **наблюдением за ванильным
сервером 26.3 по сети** через `cargo xtask probe` (без чтения кода Mojang) или по отчёту
об ошибке настоящего клиента.

## Синхронизируемые реестры: 32, а не 29

В документации нет трёх реестров, которые ванильный сервер отправляет в Registry Data:

- `minecraft:block_transformer`. Без него клиент падает при Finish Configuration:
  `Missing element ResourceKey[minecraft:block_transformer / minecraft:shovel]`.
- `minecraft:decorated_pot_pattern`
- `minecraft:worldgen/block_state_provider`

Полный список — `mc_data::SYNCHRONIZED_REGISTRIES`. Теги ваниль отправляет для 15 реестров,
наш набор совпадает с ней по реестрам и по числу тегов.

## Маски света — байтовые bit set'ы

В Light Data (Chunk Data and Update Light, Update Light) все четыре маски закодированы как
**VarInt-длина в байтах + байты** (бит `i` в байте `i / 8`, младший бит первым, хвостовые нулевые
байты отброшены). Документация до сих пор описывает их как VarInt-число long'ов + long'и.

Пример из ванильного плоского мира: `01 06 | 00 | 01 01 | 01 07`, то есть небо в секциях 1–2,
блочного света нет, пустое небо в секции 0, пустой блочный свет в секциях 0–2.

Ваниль отправляет массивы света неба только там, где он неравномерен, например у земли.
Полностью освещённые секции выше не отправляются вообще. Мы пока шлём все 26 массивов: это
корректно, но тяжелее. Оптимизация придёт вместе с `mc-light`.

## Confirm Teleportation несёт позицию

С 26.3 после Teleport ID идут итоговые X, Y, Z (Double) и Yaw, Pitch (Float). В документации
это есть, но поля легко пропустить. Ванильный сервер отключает клиента, приславшего только ID.

## Реестры без known packs: что ваниль вырезает

Если клиент не знает `minecraft:core`, ваниль присылает каждую запись реестра в NBT, но не
целиком. Вырезаются:
- `spawn_conditions` у всех `*_variant`;
- `carvers` и `features` у `worldgen/biome`;
- атрибуты окружения, нужные только серверу, в `attributes` (измерения, биомы) и `tracks`
  (таймлайны). Список — `mc_data::SERVER_ONLY_ATTRIBUTES`. Это не все `minecraft:gameplay/*`:
  `sky_light_level`, `fast_lava`, `water_evaporates` и т.п. отправляются;
- опустевший `tracks` убирается, опустевший `attributes` остаётся как `{}`.

С этими правилами `cargo xtask registry-diff` показывает 432 из 432 совпадающих записей. Числа
сравниваются по значению: тип числа клиенту не важен.

## Движение сущностей

В 26.3 у `entity_position_sync` (Teleport Entity) и `move_entity_*` есть траектории: тип 0 —
прямая к точке, тип 1 — шаги со смещением по тикам. Ваниль для игроков шлёт `move_entity_pos_rot`
с одним шагом, для мобов иногда `entity_position_sync` с шагами. Мы пока шлём
`entity_position_sync` с типом 0 и абсолютной позицией. По документации это корректно, probe
разбирает оба варианта, но настоящим клиентом пока не проверено.

## Как проверять

```bash
# локальный ванильный сервер: cache/vanilla-server/26.3 (offline, 127.0.0.1:25570, плоский мир)
cd cache/vanilla-server/26.3 && java -jar ../../../reference/26.3/server.jar nogui
cargo xtask probe --addr 127.0.0.1:25570          # ваниль
cargo xtask probe --addr 127.0.0.1:25565          # наш сервер
```

`probe` разбирает каждый знакомый ему пакет нашим форматом и сообщает о лишних байтах.
Ключ `--dump <dir>` сохраняет сырые пакеты фазы play для ручного разбора, `--mover` запускает
второго игрока, который ходит рядом: так проверяются пакеты сущностей.

```bash
cargo xtask registry-diff --a 127.0.0.1:25570 --b 127.0.0.1:25565   # реестры в NBT: ваниль vs наш
```
